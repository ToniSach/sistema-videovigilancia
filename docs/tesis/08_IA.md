# PARTE 8 — Inteligencia Artificial (Detección de Objetos)

> Subsistema en `backend/app/processing/`. Modelo: **YOLOv8-nano** (`ultralytics`) sobre **PyTorch CPU**. Diseño desacoplado y *thread-safe*: `AIFrameSource` (frames) → `AIScheduler` (orquestación, hilo worker) → `MotionDetector` (gate) → `YLOModelPool` (inferencia) → `EventManager` (eventos).

## 8.1 Cómo funciona YOLO (conceptual)

YOLO ("You Only Look Once") es un detector de objetos **single-shot**: una **única pasada** de una red neuronal convolucional (CNN) sobre la imagen produce, a la vez, **todas** las cajas, sus clases y su confianza. Esto lo diferencia de detectores de dos etapas (Faster R-CNN), que primero proponen regiones y luego clasifican (más preciso pero más lento).

**Intuición:** la imagen se procesa por una CNN que extrae características a múltiples escalas (objetos grandes y pequeños). La cabeza de detección predice, en una rejilla de celdas, para cada posible objeto:
- la **caja** (centro x,y + ancho,alto, o esquinas),
- la **objectness** (probabilidad de que haya un objeto ahí),
- la **distribución de clases** (persona, coche, …).

YOLOv8 es **anchor-free** (no usa cajas-ancla predefinidas; predice directamente la geometría) y aplica **NMS** (Non-Maximum Suppression) para eliminar cajas duplicadas del mismo objeto.

## 8.2 Cómo funciona la inferencia (matemático)

### a) Confianza de detección
La confianza final de una detección combina la objectness y la probabilidad de clase:
```
score(clase c) = P(objeto) · P(clase = c | objeto)
```
Sólo se conservan detecciones con `score ≥ conf_threshold` (en el proyecto, `AI_CONFIDENCE ≈ 0.35`).

### b) IoU (Intersection over Union) — base de NMS y de la evaluación
Para dos cajas A y B:
```
IoU(A,B) = área(A ∩ B) / área(A ∪ B)   ∈ [0,1]
```
- `IoU = 1` → cajas idénticas; `IoU = 0` → sin solape.

### c) NMS (Non-Maximum Suppression)
Elimina detecciones redundantes del mismo objeto:
```
1. Ordenar las cajas por score (desc).
2. Tomar la de mayor score, fijarla como "ganadora".
3. Eliminar las que tengan IoU(ganadora, otra) > iou_threshold (típico 0.45) y misma clase.
4. Repetir con las restantes.
```
Resultado: una caja por objeto real.

### d) Función de pérdida (entrenamiento, para contexto)
YOLOv8 entrena minimizando una suma ponderada de:
- **pérdida de caja** (p.ej. CIoU loss, mejora la localización),
- **pérdida de clasificación** (BCE sobre clases),
- **DFL** (Distribution Focal Loss para los bordes de la caja).
*(El proyecto usa el modelo preentrenado en COCO; no lo reentrena.)*

### e) Métricas de calidad (para defender resultados)
- **Precisión** = TP / (TP + FP). **Recall** = TP / (TP + FN).
- **mAP@0.5** = precisión media (sobre clases) con umbral IoU 0.5. Es la métrica estándar de COCO/YOLO.
- *Trade-off:* bajar `conf_threshold` sube recall (detecta más) pero baja precisión (más falsos positivos), y viceversa. `0.35` es un compromiso para vigilancia (preferir detectar a perder un intruso, sin inundar de falsos positivos).

## 8.3 Cómo se procesa un frame (paso a paso, código real)

### Paso 1 — Obtención del frame (`AIFrameSource`)
Lee el **substream bajo** de go2rtc (`cam_X_low`, ~360p) con FFmpeg y entrega frames fijos **640×384 BGR** a 6 fps (letterbox para preservar aspecto):
```python
vf = ("scale=640:384:force_original_aspect_ratio=decrease,"
      "pad=640:384:(ow-iw)/2:(oh-ih)/2,fps=6")
# ffmpeg ... -i rtsp://127.0.0.1:8554/cam_X_low -an -vf <vf> -pix_fmt bgr24 -f rawvideo -
frame = np.frombuffer(buf, np.uint8).reshape((384, 640, 3))   # latest-frame (newest-wins)
```
**Por qué baja resolución y 6 fps:** la CPU es el cuello de botella; 640×384@6fps reduce ~30× el cómputo frente a 1080p@30 sin perder capacidad de detectar personas/vehículos a distancia razonable.

### Paso 2 — Gate de movimiento (`MotionDetector`)
Antes de invocar YOLO, se comprueba si hay movimiento (diferencia entre frames + umbral con OpenCV). Si **no** hay movimiento, **no** se ejecuta la inferencia. Esto ahorra ~90% de las inferencias en una escena estática.
```
movimiento = (suma_de_píxeles_cambiados > umbral)
si no movimiento: descartar frame  # YOLO NO corre
```

### Paso 3 — Inferencia (`YLOModelPool`)
Una única instancia del modelo, compartida (singleton), ejecuta:
```python
results = model.predict(
    source=frame,            # numpy BGR 640x384
    conf=AI_CONFIDENCE,      # ~0.35 umbral de confianza
    classes=ALLOWED_CLASSES, # p.ej. [0]=person, [2]=car... (índices COCO)
    verbose=False,
)
```
- Salida: `results[0].boxes` con `xyxy` (coords), `cls` (índice de clase), `conf` (confianza).

### Paso 4 — Filtrado de detecciones
```python
detections = []
for box in results[0].boxes:
    cls_id = int(box.cls)
    conf   = float(box.conf)
    if conf < AI_CONFIDENCE:            # doble guarda
        continue
    if cls_id not in ALLOWED_CLASSES:   # sólo clases de interés
        continue
    x1, y1, x2, y2 = box.xyxy[0].tolist()
    detections.append({"class": COCO_NAMES[cls_id], "confidence": conf,
                       "bbox": [x1, y1, x2, y2]})
```

### Paso 5 — Agrupación por clase + cooldown
Las detecciones se agrupan por clase. Para cada clase, se aplica un **cooldown** (`AI_EVENT_COOLDOWN_SECONDS ≈ 30`): si ya se generó un evento de esa clase en esa cámara hace menos de N segundos, **no** se vuelve a emitir (evita inundar de alertas a un intruso que permanece en escena).
```
if (now - last_event_time[camera][clase]) < COOLDOWN: skip
else: emitir evento; last_event_time[camera][clase] = now
```

### Paso 6 — Publicación del evento
Se publica `EventData` al `EventManager` (clase, confianza, bbox, frame/snapshot). El bus lo persiste (`Event` + JPEG), genera el clip y dispara notificaciones (ver [03_PIPELINES.md](03_PIPELINES.md) §4–6).

## 8.4 Serialización de detecciones (formato)

```json
{
  "event_type": "person",
  "camera_id": 9,
  "confidence": 0.82,
  "bbox": [120.4, 55.1, 210.7, 340.9],     // x1,y1,x2,y2 en el frame 640x384
  "timestamp": "2026-06-07T12:00:00",
  "snapshot_path": "snapshots/cam9_20260607_120000.jpg"
}
```
El **snapshot** se genera dibujando las cajas sobre el frame con OpenCV y codificando a JPEG (optimizado por `image_optimizer`).

## 8.5 Gestión de dependencias y modelo

- **`YLOModelPool.check_dependencies()`** verifica `torch`/`ultralytics` **al activar la IA**. Si faltan, `POST /api/v1/ai/<id>/activate` devuelve **503 + `error_code: AI_DEPENDENCIES_MISSING`** con el comando `pip` exacto. *Por qué upfront:* el fallo aparece en la capa HTTP en vez de morir silenciosamente en el hilo worker.
- **Modelo `.pt`**: se carga una sola vez (singleton) y se reutiliza para todas las inferencias; los pesos (`*.pt`) están **gitignored** (no en el repo). Modelo "nano" por velocidad en CPU.
- **PyTorch CPU**: instalado con el índice `download.pytorch.org/whl/cpu` (sin CUDA) — ver `requirements.txt`.

## 8.6 Control single-camera (`AIService`, `AI_CAMERA_ID`)

- Sólo **una** cámara corre YOLO a la vez, seleccionada por `AI_CAMERA_ID`. *Motivo:* en CPU no es realista correr 4 inferencias en paralelo; se prioriza la cámara crítica.
- `AIScheduler` corre como **hilo worker** (no en el callback del `FrameDistributor` — fix F1.2), para no bloquear el reparto de frames con la inferencia lenta.
- La inferencia pasa por `InferenceQueue` (desacopla productor de modelo) con tope `MAX_AI_INFERENCE_QUEUE`.

## 8.7 Por qué este diseño (defensa)

| Decisión | Justificación |
|---|---|
| YOLOv8-**nano** | Mejor relación velocidad/precisión en CPU; cabe en hardware modesto. |
| **Gate de movimiento** | YOLO es caro; correrlo sólo con movimiento ahorra ~90% de CPU. |
| **640×384 @ 6 fps** | Reduce ~30× el cómputo vs 1080p@30 manteniendo detección útil. |
| **Substream `cam_X_low`** | La decodificación la hace go2rtc/FFmpeg (en C, fuera del GIL); Python sólo recibe el frame final. |
| **Cooldown por clase** | Evita inundar de alertas; una persona estática genera 1 evento, no 100. |
| **Una cámara (`AI_CAMERA_ID`)** | CPU limitada; abre la puerta a GPU (QSV/CUDA) por configuración. |
| **`check_dependencies` upfront** | Falla con 503 claro y el `pip` exacto, no muere en silencio. |

## 8.8 Riesgos y mejoras

- **Riesgos:** falsos positivos del gate de movimiento (lluvia/iluminación); una sola cámara con IA; latencia de detección en CPU; umbral fijo.
- **Mejoras:** sustracción de fondo adaptativa (MOG2) y ROIs para el gate; soporte GPU multi-cámara con cola priorizada; *tracking* (ByteTrack) para contar/segregar objetos; ajuste dinámico de `conf` por escena; clasificación de eventos (merodeo vs cruce) usando trayectorias.

## 8.9 Ejemplo numérico de defensa

> "Con `AI_CONFIDENCE=0.35` y NMS a IoU 0.45: si la red propone para una persona dos cajas con scores 0.82 y 0.76 e IoU 0.7 entre ellas, NMS conserva la de 0.82 y descarta la de 0.76 (misma clase, IoU>0.45). La detección final (0.82 ≥ 0.35) pasa el filtro, se agrupa como clase `person`, y si no hubo otra `person` en los últimos 30 s en esa cámara, se emite un evento con su snapshot y clip."
